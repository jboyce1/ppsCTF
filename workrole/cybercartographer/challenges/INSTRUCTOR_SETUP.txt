CYBERCARTOGRAPHER — INSTRUCTOR RUN SHEET
Run one command at a time. Finish each step before moving on.
Keep this guide on your instructor computer; copy commands into the range VM.

A. INSTRUCTOR COMPUTER — REFRESH THE CLASS LIST

1. Launch the assigned CYBER.ORG VMs. Open the classroom inventory.
   Copy the inventory page text; extra names and labels are fine.

2. In VS Code, open cyberorg_classroom_targets_dirty.txt in cybercartographer.
   If the file is missing, create a text file with that exact name in this folder.
   Replace its contents with the inventory (Ctrl+A, Ctrl+V), then save (Ctrl+S).

3. In your local cybercartographer terminal, clean the list:

python3 cyberorg_classroom_targets_cleaner.py

   Check the saved address count before continuing.

4. At "Open GitHub to publish this list? [y/N]", type y and press Enter.
   In VS Code, open cyberorg_classroom_targets.txt; select all and copy.

5. In the GitHub file editor, replace the old file text with the clean list.
   Click Commit changes and confirm the commit to main.

   If the editor did not open, use this on your instructor computer:
   https://github.com/jboyce1/ppsCTF/edit/main/workrole/cybercartographer/cyberorg_classroom_targets.txt

   The cleaned list contains assigned IPs; it does not prove the VMs are online.

B. TARGET VM — INSTALL THE TRAINING SERVICES

6. Open the assigned Ubuntu/Kali VM console. In the file manager, open Desktop,
   then right-click an empty area and open a terminal there.

7. Download the launcher (this replaces an older downloaded copy):

wget -O deploy-target.py https://raw.githubusercontent.com/jboyce1/ppsCTF/26979c6b5f4ba58a16ac30ad64e49e7f6a291b5d/workrole/cybercartographer/challenges/flagscripts/deploy-target.py

   Continue only after the download succeeds.

8. Run the launcher:

sudo python3 deploy-target.py

   Enter the VM account's password if sudo asks. Check that the title says v2.2.

9. At Options, enter 148 for the first trial:
   SSH 22 + anonymous FTP 21 with a file flag + Telnet 23 with a banner flag.

   Other recipes (choose ONE recipe for a VM):
   136 = SSH 22 + FTP 21 + Telnet 23, without new flags.
   248 = high-port SSH + FTP 21 with flag + Telnet 23 with flag.
   259 = high-port SSH + high-port FTP + high-port Telnet with flag.
         For 259, answer y when asked whether to add an FTP flag.

   Full menu:
   1 SSH 22                 2 SSH high port
   3 FTP 21                 4 FTP 21 with flag
   5 FTP high port (asks about adding a flag)
   6 Telnet 23              7 Telnet high port
   8 Telnet 23 with flag    9 Telnet high port with flag

10. At FTP login, press Enter for anonymous.
    Use both only when you want anonymous AND existing VM-user FTP access.
    Use user for user-only FTP without an anonymous flag.

11. Review the printed plan. At "Apply to this VM? [y/N]", enter y.
    Wait for the final inventory. Installed packages are reused; missing packages
    show installation progress. Do not start a second setup while one is running.

12. Read the final inventory: VM IP, service, TCP port, access mode, result, flag.
    If any row says FAIL, SETUP FAILED, or NOT CHECKED, use the help section below.

13. Copy the final inventory into your class notes. Save the report folder.
    inventory.txt is the same table; validation-handoff.txt contains the next commands.

    These are LOCAL checks. Now test from a separate Kali VM.
    For a different recipe, use a fresh/reset target VM; rerunning can leave old
    Telnet listeners and old flags. Do not assume rerunning removes earlier services.

C. KALI VM — TEST WHAT STUDENTS CAN REACH

14. On a separate Kali VM, open Desktop in the file manager.
    Right-click an empty area and open a terminal there.

15. Download the validator:

wget -O validate-target.py https://raw.githubusercontent.com/jboyce1/ppsCTF/main/workrole/cybercartographer/challenges/flagscripts/validate-target.py

    Continue only after the download succeeds.

16. From the TARGET's final "NEXT — ON KALI" block, copy the scp command for its
    classroom IP. Run that command in the KALI terminal. It already includes the
    target username, IP, SSH port, and expectations.json path.

    If SSH asks about a new host key, confirm the target identity before accepting.
    Enter the TARGET account's password. Wait for the copy to finish successfully.
    If SCP is unavailable, copy expectations.json through the classroom fileshare.

17. On Kali, confirm that the copied file is present:

ls -l expectations.json

    If the file is missing or the copy failed, STOP and repeat step 16.
    Use the latest file from THIS target, not a plan left over from another VM.

18. Run the comparison:

python3 validate-target.py --expect expectations.json

19. Enter the TARGET's classroom IP. Then enter the TARGET's existing non-root
    username and password. The password is hidden and is not saved.

20. Wait for OVERALL: PASS. Confirm the IP, ports, flags, and login checks match
    your target notes. Save student-summary.txt from the printed report folder.

    FAIL = a required check failed; use the help section.
    INCOMPLETE = something was skipped, no plan was used, or an unexpected open
    port needs review. Read those rows before treating the target as ready.

D. STUDENT KALI — DOWNLOAD THE CURRENT CLASS LIST

21. In the team's shared folder, open a terminal. Download the published list:

wget -O cyberorg_classroom_targets.txt https://raw.githubusercontent.com/jboyce1/ppsCTF/main/workrole/cybercartographer/cyberorg_classroom_targets.txt

head cyberorg_classroom_targets.txt

    Confirm these match the current class allocation. Continue with the student

QUICK HELP — ONLY USE THE MATCHING FIX

"No such file: expectations.json"
Return to step 16 on Kali. The file starts on the TARGET, not on Kali.

"SSH login needs python3-paramiko"
On KALI, install the validator dependency:

sudo apt-get install -y python3-paramiko

Then repeat step 18. Do not skip login checks to get a passing result.

"FTP server is anonymous only"
Anonymous-only FTP is expected for the first trial. Make sure you used the latest
expectations.json with --expect. If the plan requires both/user, inspect the target
setup report rather than treating a rejected user login as a successful setup.

Unexpected open ports / changing to another recipe
Use a fresh/reset target for a clean trial. Older services may still be running.
A launcher run configures selected services; it does not erase the VM's history.

Recheck an existing target WITHOUT changing its high ports
On the TARGET, run the following after replacing REPORT_FOLDER with the exact
printed report directory (put quotes around the path if it contains spaces):

sudo python3 deploy-target.py --check REPORT_FOLDER/expectations.json

Broader check for old listeners
On KALI, scan all TCP ports using the copied plan (takes longer):

python3 validate-target.py --expect expectations.json --ports 1-65535

Student scans: filename and progress checks
Use hostsup.txt for ALL student service scans. It contains responding IPs only.
cyberorg_classroom_targets.txt is the assigned inventory; discovery.gnmap and
service reports are scan output. Do not rename or copy the list to hosts.txt.
The updated normal and MOVE lessons use progress output every five seconds,
60-second per-host limits for standard ports, five minutes per host for the wider
high-port scan, and 15-second script limits. These are not whole-class deadlines.
Telnet/high-port scans find open ports first, then identify one service at a time.
Wait for Nmap done. Timeouts/interrupted scans are INCOMPLETE; missing script
output is UNKNOWN. Do not record either as "no services" or a successful check.

Next live classroom check
Repeat the updated student discovery and Telnet walkthrough against a fresh
known-working target. Confirm hostsup.txt contains its IP, progress is visible,
the open port is found, service identification finishes or reports a timeout,
and the Telnet login succeeds. The exact cause of the earlier silent scan has
not been established; these changes expose progress and bound per-host work.

Anything else fails
Save the TARGET's target-summary.txt, diagnostics.txt, and run.log, plus KALI's
student-summary.txt. These show what failed. Do not repeatedly reinstall blindly.
